# Mirror Sync — GitHub / GitLab

Источник истины проекта — self-hosted Forgejo. GitHub и GitLab — зеркала
только для чтения по конвенции: коммитить в них напрямую не следует.

## Маппинг веток

| Forgejo (источник) | GitHub | GitLab |
| --- | --- | --- |
| `main` | `main` | `chimera-v5` |
| прочие ветки | та же ветка | та же ветка |

GitLab-зеркало живёт в канонической ветке **`chimera-v5`** — именно на неё
ссылается команда установки (bootstrap-зеркало №2:
`…/-/raw/chimera-v5/bootstrap.sh`), README и тесты
(`tests/test_bootstrap_mirrors.py`). Ветки `main` на GitLab нет; дефолтная
ветка проекта — `chimera-v5`.

## Механизм (двухуровневый)

**Основной — на хосте Forgejo (мгновенный fan-out):**

- post-receive hook репозитория → `chimera-mirror.sh` (sudo, без пароля):
  сразу после каждого пуша в Forgejo забирает `main` и толкает его на оба
  зеркала с учётом маппинга (GitHub `main`, GitLab `chimera-v5`).
- `chimera-mirror.timer` — страховочный прогон каждые 3 минуты
  (навёрстывает пропущенное после даунтайна).
- Токены — только в защищённом env-файле на хосте (root:root 600);
  пуш с force: зеркало приводится к состоянию Forgejo.

**Страховочный — второй хост (ежечасно, с алертами):**

- `chimera-mirror-sync.timer`: тот же маппинг веток, пуш БЕЗ force.
  Догоняет упущенное (fast-forward), а если выровнять зеркало нельзя
  (расхождение историй) — TG-алерт `[mirror-sync] FAIL`: канарейка
  здоровья зеркалирования, закрывает молчаливость мгновенного fan-out.
- Лог: `/var/log/chimera-mirror-sync.log` (ротация logrotate).

## Почему зеркала могут «замёрзнуть»

Родной механизм решает «есть ли новые коммиты в источнике», а не
«сошлись ли зеркала», и вывод мгновенного fan-out не журналируется.
Поэтому при расхождении историй зеркала молчат до ручного выравнивания —
ежечасный страховочный прогон с TG-алертом служит ранним сигналом.

Типичный сценарий расхождения — «коммит-близнец» на зеркале: та же правка,
запушенная вручную минуя Forgejo (другой sha → параллельная история).
Дальнейшие автопуши становятся non-fast-forward и отвергаются защитой
веток зеркал. Ручные синки зеркал не создавайте — коммитьте в Forgejo.

## Управление

```bash
# хост Forgejo — основной механизм
journalctl -u chimera-mirror -f              # журнал страховочных прогонов
systemctl start chimera-mirror.service       # прогнать сейчас

# второй хост — страховочный механизм
systemctl start chimera-mirror-sync.service  # синкнуть сейчас
tail -f /var/log/chimera-mirror-sync.log     # живой лог
```

## Если зеркала разошлись

Основная причина — прямой коммит в зеркало в обход Forgejo (см. выше).
Решение: закоммитить правку в Forgejo (источник истины) и выровнять
зеркало force-push'ем: временно снять защиту ветки через API хостинга,
запушить, вернуть защиту 1:1. После выравнивания основной механизм
продолжает работу в штатном fast-forward-режиме.
