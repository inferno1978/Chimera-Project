# Changelog new entry — FIX(panel_nginx_front): nginx-front порты НЕ регистрировались в port_registry — port_register после reload ловил собственного слушателя (тихий False, возврат не проверялся); реестр врал по всем 5 панелям годами (01 Nov 2026)



## Решение:
- шаг 6: port_register(..., force=True) — конфликт-проверка ДО поднятия слушателя уже сделана в шаге 1, здесь фиксация; возврат проверяется (reg_ok): провал → warn, не прерывает установку (UFW/vhost уже стоят);
- шаг 1: check_port_via_registry(port, tag, ignore_system_nginx=True) — новый параметр: system-конфликт от слушателя nginx (наш собственный при пере-установке) не блокирует; чужой процесс (не-nginx) и чужие registry/UFW записи — честный конфликт как раньше; дефолт False — семантика остальных вызовов не изменилась.



---



- _render_acme_vhost(domain): listen 80 + server_name <поддомен> + acme-root /var/www/<поддомен>; location / → тихий 404 (не палим порт 3443 в Location-заголовке — маскировка, эталон b4);
- _ensure_acme_vhost(domain): webroot mkdir + vhost + symlink + nginx -t + reload; идемпотентно; без nginx (CI) — тихий False; провал НЕ роняет установку (серт может уже существовать);
- _nginx_install: LE-ветка зовёт _ensure_acme_vhost ДО panel_nginx_front_install (obtain_ssl_cert → certbot --webroot); self-signed-ветка не тронута;
- _nginx_remove: _remove_acme_vhost() в обеих ветках (включая «уже выключен» — чистит осиротевший vhost после сбоя);

Решение по портам: апстримный маппинг «0.0.0.0» сознательно патчится на loopback (а не ufw deny) — панель не торчит из docker-proxy вовсе; nginx front остаётся единственной дверью наружу, эталон b4 «ufw deny прямого порта» соблюдён сильнее — порта просто нет снаружи.
