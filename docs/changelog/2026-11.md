# Changelog new entry — FEAT(awg-mieru): аддон «AWG 3.1 поверх Mieru» — клиентский UDP-мост SOCKS5 UDP ASSOCIATE, выдача бандла пир+mita-юзер, TUI+CLI, откат (02 Nov 2026)

## Контекст: продолжение линии hybrid_addon (Mieru поверх Xray). Вопрос владельца: можно ли аналогично завернуть AWG 3.1 — клиент подключается по mieru, дальше весь трафик в туннеле AmneziaWG. Ключевой механизм — НЕ SOCKS5-CONNECT (как у Xray), а SOCKS5 UDP ASSOCIATE: сервер WireGuard/AWG отвечает пиру по адресу последней валидной датаграммы (endpoint roaming), mita держит UDP-сокет на время ассоциации → awg0 на Entry видит «пира с адресом mita» и работает штатно. Живая валидация на entry-ноде (02.11.2026, mita/mieru 3.38.0): UDP ASSOCIATE через mieru→mita доставляет датаграммы вплоть до 127.0.0.1 и до собственного публичного IP:порт awg0 — TCP CONNECT и UDP echo подтверждены end-to-end; на проводе 138x→EU mieru НЕ несёт TLS ClientHello вообще (tshark не находит handshake, первые байты high-entropy) — «маяк» MLKEM768/SNI/JA3 неприменим по построению. Схема клиентского mieru-профиля (profileName / user{name,password} / servers[].portBindings[{port,protocol}] / socks5Port) сверена оракулом `mieru replace config` на реальном бинарнике — легаси-поля port/protocols отвергаются, рабочая схема принята.

## Решение — новый модуль chimera/modules/awg_mieru_addon.py (самостоятельный, stdlib-only, паттерн hybrid_addon; все импорты chimera — ленивые внутри функций):
1. **Сервер: ноль изменений инфраструктуры.** Не трогает awg0, AWG-каскад, mita, порты, firewall. Добавляет только: AWG-пир (штатный awg_peer_add) и mita-юзер awg_<имя> (регенерация server.json через примитивы mieru.py — _build_server_config/_apply_server_config, те же, что в ensure_user_full).
2. **Клиентский бандл** /root/awg-mieru/<name>/: awg-client.conf (штатная сборка awgs_qr_build_client_conf + патч Endpoint=127.0.0.1:<gw_port>, MTU=1100 — консервативно как AWG31_MTU в wpp_awg: mieru MTU 1400 − padding ≤128 − заголовки), mieru-client.json (оракул-сверенная схема), mieru-udp-gw.py (мост), start-linux.sh, start-windows.bat, README.txt (стек, порядок запуска, компромисс TCP-over-TCP, откат).
3. **Мост mieru-udp-gw.py** — UDP→SOCKS5(UDP ASSOCIATE), только stdlib, selectors-петля: сессия per client-addr (TCP control + relay UDP), обёртка RSV/FRAG/ATYP/DST, разворот ответов с корректным парсом ATYP 1/3/4, idle-GC 180 c (keepalive 25 с держит живые тёплыми). E2E протестирован локально: mock-SOCKS5 с UDP ASSOCIATE + fake-AWG-echo → 5/5 датаграмм клиент→мост→SOCKS5→«awg0»→обратно.
4. **CLI**: --status / --issue NAME [--gw-port --socks-port --entry] / --regen NAME (смена IP/домена Entry — пересборка бандла) / --revoke NAME / --list / --rollback-all. **TUI**: do_awg_mieru_menu() — пункт [M] в меню управления пирами AWG (do_manage_awg_peers). State: /var/lib/xray-installer/awg_mieru.json (schema 1, права 0600).
5. **Идемпотентность и откаты**: issue откатывает mita-юзера при падении awg_peer_add; revoke удаляет пир+юзер+бандл; rollback-all — всех; regen не трогает ключи (только бандл). Лог в /var/log/chimera.log.

**Компромиссы (задокументированы в README бандла):** TCP-over-TCP для TCP-нагрузки внутри туннеля (браузение терпимо, торренты плохо; UDP-нагрузка страдает меньше); MTU 1100; синхронизация времени ±30 с (требование mieru). Сегмент клиент→Entry при этом полностью теряет TLS-отпечаток И UDP-ногу (UDP-квоты/шейпинг неприменимы — нога TCP); AWG 3.1-обфускация (I1-I5, HeaderProtectionKey, padding, trailers) сохранена как есть.

**Не входит (намеренно, возможные следующие шаги):** интеграция с TG-ботом (/config-сегмент), rest_api-синк в WPP-портал, QR для mierus-части (мобильный стек mieru+AWG не собирается одним приложением — Karing/NekoBox не умеют AWG I1-I5).
