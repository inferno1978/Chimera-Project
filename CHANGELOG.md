**Корень:** awg31_generate_extra_params считает reject_low = rekey_high(≤160) + randint(30,60) → максимум 220, затем верх = reject_low + randint(30,90) → максимум 310 при капе валидатора AWG31_RANGE_KEYS reject_after_time (130, 300). Максимальный путь: rekey 120+40=160, reject 160+60=220, верх 220+90=310 > 300. Не только флак теста: это РЕАЛЬНЫЙ прод-баг — каждый ~1600-й сгенерированный конфиг 3.1 не проходил собственную кросс-валидацию (для юзера — нестабильная генерация конфига).

**Фикс (оба генератора, «единый отпечаток генерации»):** ширина окна ограничивается головником до капа — randint(30, min(90, 300 - reject_low)); reject_low ≤ 220 → головник ≥ 80 ≥ 30, окно никогда не вырождается (минимум 250-300 при клампе). awg_protocol.awg31_generate_extra_params + wpp_awg._parameters("awg31") (дубль той же формулы — чинились синхронно). Сид-детерминизм сохранён (структура вызовов rng не изменилась).

**Тесты:** test_awg_protocol_31 43→45: test_reject_after_time_never_exceeds_cap — детерминированный максимальный путь (rng-двойник, всегда возвращающий верхнюю границу randint: без фикса даёт ровно 310 > 300, с фиксом — 300 ровно на капе, окно не вырождено ≥250, весь набор валиден); test_generation_statistically_valid — 2000 случайных генераций без невалидных (до фикса ловила бы с вероятностью ~70%). Сканер доступен и как CLI: scripts/fstring_compat_scan.py (выход «файл:строка: причина», exit 1 при находках).

# Changelog new entry — AGH статус: Web UI показывает ОБА входа с подписями способа доступа — браузером :30443 / SSH-туннелем :3000 (24 Oct 2026)

## FEAT(aghome)/UX: кейс юзера «зашёл https://chimeraprodcdn.online:3000 → ERR_SSL_PROTOCOL_ERROR» — строка статуса «Web UI: :3000 ✓ (https_le)» вводила в заблуждение: показывала ОДИН порт (plain-HTTP, wizard-вход), тогда как браузерный вход в TLS-режимах живёт на :30443 (Web UI + DoH мультиплексированы native-TLS AGH), а :3000 снаружи закрыт UFW и доступен только с сервера или по SSH-туннелю. Принцип новой выдачи: ПОРТ СЛЕДУЕТ ИЗ СПОСОБА ДОСТУПА, а не наоборот.

**Статус-бокс (print_aghome_status):** строка режима теперь с человекочитаемым ярлыком вместо внутреннего кода (`_web_mode_label`: https_le → «HTTPS + Let's Encrypt», https_self → «HTTPS + self-signed», http_public → «HTTP публично», loopback → «локально — SSH-туннель»), под ней — строки входов по режиму:
- TLS-режимы: `браузером: https://<домен-или-IP>:30443` + `SSH-туннелем: http://127.0.0.1:3000 (порт :3000 снаружи закрыт)` + готовая команда туннеля `ssh -L 3000:127.0.0.1:3000 root@<IP>` (конвенция wpp_panel; при приватном/неопределимом IP команда не показывается);
- TLS упал (self-heal downgrade): браузерного https-входа нет — только туннель, рядом честная строка «TLS: выключен»;
- http_public: `браузером: http://<host>:3000 (plain HTTP)`, туннельные строки не показываются (режим публичный);
- loopback: `SSH-туннелем: http://127.0.0.1:3000 (только 127.0.0.1)` + команда туннеля.
Попутный косметический фикс: дублирование «self-signed (self-signed)» в TLS-строке при https_self без домена — теперь просто «self-signed».

**Финализация (finalize_aghome_config):** итоговые info-строки печатают те же оба входа по режиму — TLS: «Web UI (браузером): https://<host>:30443» + «Web UI (SSH-туннелем): http://127.0.0.1:<port> (порт снаружи закрыт)»; http_public: браузерный http-URL; loopback: туннельный URL (раньше при дефолтном порте loopback/TLS молчал вовсе, а http_public печатал URL без указания способа доступа).

**Хелперы:** `_web_mode_label()` (человекочитаемые ярлыки режимов) и `_webui_tls_host()` (хост ссылок: домен TLS-режима → публичный IP → пусто; приватный IP не подставляется — ссылка была бы бесполезна); `_client_dns_links()` переиспользует `_webui_tls_host` (поведение байт-в-байт).
