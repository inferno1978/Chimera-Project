# Changelog new entry — feat(fragment): DUAL-схема noise-зеркала finalmask — freedom.noises дублируется в streamSettings.finalmask.udp (маска "noise") с матрицей совместимости fragment-dual; точечный рубильник CHIMERA_FINALMASK_NOISE (18 Nov 2026)

DUAL-схема fragment (31.10) уже зеркалит fragment в finalmask.tcp, но шум (пресеты light/medium/aggressive комбо-генераторов fragment_noise/fragment_link) оставался ТОЛЬКО в legacy-паре: при реальном срезе полей ядрами пост-миграции шум молча исчез бы из клиентских конфигов. Сверка исходников Xray-core (клон HEAD 7daa8e4, 18.11): маска "noise" зарегистрирована в udpmaskLoader (infra/conf/transport_finalmask.go:93), NoiseItem несёт rand (Int32Range — длина случайного шума) и delay (Int32Range — диапазон мс); по тегам репозитория маска и поля стабильны с v26.7.28 (июль 2026) и присутствуют во ВСЕХ ядрах, знающих finalmask, — отдельный гейтинг по версии ядра (паттерн FP_CLIENT_ONLY/hellochrome_155) НЕ требуется. Соседний шум заголовка новости — XMC finalmask «нативный padding фреймов, несовместимо, delay-диапазон» (коммиты f781c68/a32023b/82b5b76): XMC — Minecraft-обфускация, отдельный тип tcp-маски; НЕ Химера-путь: по тегам XMC-padding не вышел ни в одном релизе, а неизвестный тип маски на ядрах без него = «unknown config id», отказ всего конфига (дискриминатор-1 из деплоя 31.10).

## Решение: fragment_config.py — новый build_stream_finalmask_noise(packet, delay) → {"type":"noise","settings":{"noise":[{"rand": packet,"delay": delay}]}}: легаси-поле packet при type="rand" переносится в NoiseItem.rand — «type» в NoiseItem означает ТИП КОНТЕНТА фиксированного packet (str/hex/base64/array), легаси-"rand" туда переносить НЕЛЬЗЯ («unknown type», отказ конфига); delay — Int32Range, формат идентичен легаси; reset не задаётся: ResetMax=0 → шум one-shot на адрес (transport/internet/finalmask/noise/conn.go:111) — семантика легаси firstWrite (первый UDP-пакет потока). apply_stream_finalmask(+noise_packet, +noise_delay, опциональны): комбо → finalmask = tcp[fragment]+udp[noise]; шум без фрагмента (пресет «0») → маска из одной udp-записи; без noise-аргументов → прежнее поведение (только tcp). Рубильники: точечный CHIMERA_FINALMASK_NOISE=0 (глушит только noise-запись, tcp-зеркало живо); общий CHIMERA_FRAGMENT_FINALMASK=0 глушит finalmask целиком — фикс в apply: раньше noise-запись собиралась до проверки общего рубильника и просачивалась мимо него (поймано новым тестом). DUAL, а не замена: legacy-пара (freedom.settings.noises + sockopt.dialerProxy) не снимается ни в одном генераторе. Точки вызова с шумом: fragment_noise._build_xray_noise_json, fragment_link._build_xray_client_json (комбо-путь), generate_fragment_client_config (комбо-пресеты) — все три прокидывают noise_packet/noise_delay; mux/fuzzer шумов не несут — вызовы не тронуты (обратная совместимость опциональных параметров). Sing-box билдеры НЕ тронуты (у sing-box нет finalmask — свои dial-поля NekoBox/Hiddify). Матрица совместимости: ядра до finalmask (от 1.8.3 до ~июля 2026) — поле игнорируют целиком (encoding/json), работают по legacy-паре как раньше; v26.7.28+ — парсят noise-маску валидно; пост-миграционные (noises срезан) — читают finalmask.udp как единственный источник шума.

# Changelog new entry — feat(nginx-stub): идемпотентный HSTS-апгрейд живых vhost'ов — upgrade_vhosts_hsts(): флотовый rollout фикса 8824000 без переустановки (бэкап + nginx -t гейт + rollback + dry-run) (16 Nov 2026)

## Контекст: фикс 8824000 добавил HSTS в ШАБЛОНЫ заглушек (own-site, xHTTP-main, REALITY-маска), но живые конфиги на нодах генерировались раньше — переустановка nginx-части ради одной строки на каждой ноде флота избыточна и рискованна (merge-логика own-site/REALITY-сокетов в одном vhost тонкая — см. 2e39801). Для РКН-волны нужен безопасный однотипный инструмент применения на всех нодах флота (RU-entry + exit), не зависящий от того, каким релизом генерился живой конфиг.

## Решение: nginx_setup.upgrade_vhosts_hsts(apply=True) — идемпотентный мигратор живых vhost'ов: (1) скан sites-enabled, симлинки резолвятся к target'у в sites-available; (2) top-level server-блоки (баланс скобок — та же техника, что _extract_server_blocks_with), содержащие X-Robots-Tag (маркер chimera-заглушки) и НЕ содержащие Strict-Transport-Security, получают add_header Strict-Transport-Security "max-age=63072000" always; с тем же отступом, что строка X-Robots-Tag; (3) блоки с HSTS (фронты панелей) не трогаются — двойной заголовок исключён по построению; блоки без маркера (ACME :80, default reject, чужие vhost'ы) не трогаются вовсе; (4) перед правкой — бэкап <файл>.bak-hsts-<ts> рядом с target'ом; (5) nginx -t — гейт: провал → полный rollback всех изменений этого прогона, ok=False; (6) systemctl reload nginx — только при изменениях; повторный прогон — полный no-op (0 вызовов _run, новых бэкапов нет). Вызов на ноде после git pull: cd /opt/chimera && python3 -c "from chimera.modules.nginx_setup import upgrade_vhosts_hsts; import json; print(json.dumps(upgrade_vhosts_hsts(), ensure_ascii=False, indent=1))". Хелпер _iter_top_level_server_blocks — общая переиспользуемая замена ручного перебора блоков.
